What the redesign assumes

  • Spectrogram viewer is new frontend + a new backend endpoint. Today spectrograms are rendered server-side only (./tmp/tmp.png) for inference and deleted. The viewer needs a route that serves the spectrogram image (or PSD tiles) plus detections in time/frequency coordinates.
  • Frequency bounds already exist — they just aren't stored. The pipeline computes fmin/fmax per detection but drops them at the DB boundary. Drawing frequency-accurate boxes needs two new DETECTIONS columns.
  • Confirm / reject needs an addressable detection. A review state column and use of id_detection in the API (currently never selected).
  • Live progress replaces the 9-step broadcast with per-window updates scoped to the uploading client.
  • Sample data in these mockups is illustrative; the real sample project has two labelled species (blue whale, fin whale) and the detector recognises two classes.
